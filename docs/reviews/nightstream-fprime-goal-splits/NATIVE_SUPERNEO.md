# Independent source review: native SuperNeo first

Proposal 1 is to finish the executable SuperNeo core in Lean and Rust, with complete conformance, before the recursive circuit and HyperNova.

The native folding calculations can close before the F′ fixed point. The current source does **not** establish a standalone secure protocol for arbitrary caller-selected running claims. The digest-only transcript requires an authenticated statement boundary. Goal A must either own that checked boundary or state it as an explicit precondition. If it keeps the precondition outside Goal A, its result is a native folding core, not a standalone secure SuperNeo system.

This review assumes the existing Nightstream Goldilocks profile: `b = 2`, `k_rho = 16`, `B = 2^16`, one fresh source, sixteen running sources, and seventeen PiRLC inputs. These values come from the project policy and architecture contract. No alternative profile, new backend, new package, or general protocol framework is proposed. The current production Lean shape also fixes fourteen matrices and twenty-eight rounds. Small native tests do not prove that complete shape. ## Required statement-binding boundary

The prior digest is not taken from the same field in the two current interfaces:

- Lean `ProductionKey.priorDigest` reads `decodeHash(fresh.publicInputs[0])`. `publicInputBlocks` ignores `running` and absorbs that digest, the fresh commitment, and the fresh public input. [ProductionKey.lean:100](/Users/nicarq/starstream/develop/nightstream-clean-up/formal/nightstream-fprime/NightstreamFPrime/Lifecycle/ProductionKey.lean:100)
- Rust `prior_digest_fields` reads `running[0].fold_digest`. It checks only that all running digest fields agree and contain canonical field words. It then absorbs that digest and the fresh claims. [pi_ccs_joint_protocol.rs:75](/Users/nicarq/starstream/develop/nightstream-clean-up/crates/neo-reductions/src/engines/pi_ccs_joint_protocol.rs:75), [absorption:197](/Users/nicarq/starstream/develop/nightstream-clean-up/crates/neo-reductions/src/engines/pi_ccs_joint_protocol.rs:197)
- The Rust parity fixture supplies the same prior-state digest to each running claim explicitly. It also checks the fixture's public block values. This establishes the chosen fixture mapping, not a general native-entrypoint equality. [pi_ccs_lean_nonzero_parity.rs:291](/Users/nicarq/starstream/develop/nightstream-clean-up/crates/neo-fold-clean/tests/nifs/pi_ccs_lean_nonzero_parity.rs:291)

Lean has a `verifierInputBlocks` definition for the prior point and running evaluations, but the selected `piCcsOracle.initialState` returns the supplied prior state unchanged. Those blocks are not reabsorbed by this oracle. `key_oracle_initialState_eq` states that the pilot digest owns this binding. Neither check recomputes a state hash from the complete ordered running statement and verifier context. The `RunningInstance` fields and constructor do not add that authority. Its comments about binding an exact child handle and parent-cache digest must not replace the current executable trace. ## Concrete migration work

1. **Authenticate the native statement and align its digest input with Lean.** The current digest-only interface relies on a state-binding layer. This is the first security boundary to settle for Proposal 1.
2. **Close composed native parity with valid openings.** The current PiRLC parity test calls `sample_rho_n`, public combination, and engine verification. It does not call the native `paper::pi_rlc::verify` or the complete NIFS wrapper on the same Lean fixture. A complete Goal A check must start from the same validated relation, commitment key, fresh/running inputs, and proof, and compare the complete native and Lean results. [pi_rlc_lean_nonzero_parity.rs:457](/Users/nicarq/starstream/develop/nightstream-clean-up/crates/neo-fold-clean/tests/nifs/pi_rlc_lean_nonzero_parity.rs:457)
3. **Resolve the post-PiRLC projection boundary.** Native PiRLC computes quotient metadata, appends a projection binding digest, and squeezes beta after sampling. Lean PiRLC exports `batch.finalState`. This is a concrete schedule difference. It is not a measured claim-output mismatch. The combined claim is unchanged; PiDEC has no transcript argument; the NIFS proof omits projection metadata; and the next PiCCS resets its transcript. The extra operations can affect an external consumer of the returned transcript. Exact outgoing-state conformance needs a defined endpoint or removal/separation of that native-only step. [pi_rlc.rs:668](/Users/nicarq/starstream/develop/nightstream-clean-up/crates/neo-fold-clean/src/paper/reductions/pi_rlc.rs:668), [PiRLCParity.lean:191](/Users/nicarq/starstream/develop/nightstream-clean-up/formal/nightstream-fprime/NightstreamFPrime/Export/Stage1/PiRLCParity.lean:191)
4. **Separate fixture authority from the F′ fixed point where Goal A needs independent execution.** The mathematical NIFS and native prover/verifier have no necessary recursive-size dependency. Current `PiCCSNonzero` and `PiCCSInputCheck` obtain widths and authority from `Poseidon2HashChainV1Package` and `PerApplicationFixedPoint`. Keep the same protocol definitions and expose only the concrete executable boundary needed by native conformance. Do not duplicate the folding semantics or create a second production package. [PiCCSNonzero.lean:1](/Users/nicarq/starstream/develop/nightstream-clean-up/formal/nightstream-fprime/NightstreamFPrime/Export/Stage1/PiCCSNonzero.lean:1), [PiCCSInputCheck.lean:28](/Users/nicarq/starstream/develop/nightstream-clean-up/formal/nightstream-fprime/NightstreamFPrime/Export/Stage1/PiCCSInputCheck.lean:28)

Moving whole crates, replacing the existing folding algebra, adding generic profiles, or finishing the recursive fixed point is not shown to be necessary for Goal A. The current native implementation is substantial reusable work. Its complete authenticated-input and conformance contracts need to be finished.
