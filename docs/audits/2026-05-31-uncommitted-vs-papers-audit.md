# Soundness Audit Report — `nico/update_multi_parallel_fold_support`

*Generated 2026-05-31 by a 29-agent workflow auditing all 98 uncommitted changed files against the SuperNeo (§4–7, App D) and HyperNova (§3–6, App H.1, A.4) papers. 50 paper invariants distilled; every critical/high/medium finding adversarially re-verified against code + paper. Read-only — no builds or tests were executed.*

## Verdict

This branch is **soundness-positive overall** and contains **no verifier-accepts-invalid (critical) defect**. The headline change — upgrading the carried Construction-2 / Π_CCS accumulator handle from a commitment-only digest to a full running-instance (`U_i`) digest, mirrored field-for-field across native prove, native verify, and the in-circuit decider — *strengthens* binding toward HyperNova's `NIVC-DIGEST-IO-BINDING` and `MF-STRUCTURE-DIGEST-BINDING`, and the new in-circuit RLC/DEC `fold_digest` checks close a real native↔circuit parity gap (digest-as-authority-without-recomputation) on the recursive path. The multi/parallel-fold algebra (per-instance ρ/γ separation, Toom-3 ring multiply, fold-before-matrix Eval table, CSC/tensor/Ajtai kernels) is value-preserving and faithful to SuperNeo Sec 4–5. **One issue blocks the prove→compress recursive link** (NFC-1, high): the native `state_x_out_digest` was left on the old full preimage while the circuit + parity test migrated to a reduced compact-domain preimage — an incomplete migration that renders the decider/F'-step R1CS unsatisfiable and reds three committed tests. It is a liveness/correctness break, not a false-accept. The remaining real defects are two medium preprocess-validator gaps in the R1CS-F' frontend (non-injective packed public-input binding; Boolean detector assuming an unpinned constant lane) and two low-severity completeness regressions on the parallel Eval path (negligible ~1/|F| trigger, no soundness impact). Recommend: fix NFC-1 before relying on compress, fix the two medium frontend gaps, and patch the two low Eval-table skips opportunistically.

## Critical & High

There are **no critical (verifier-accepts-invalid) findings**. One **high** finding:

### NFC-1 — Native `state_x_out_digest` left on old full preimage while circuit + parity test migrated to reduced preimage (native↔circuit divergence)

- **What is wrong:** The in-circuit `state_x_out` digest was reduced to a compact single-field domain (`F_PRIME_STATE_X_OUT_DOMAIN = 0x4e46_0002`) over only `{vk_fs, step_count, initial_boundary, current_boundary, semantic_acc, construction2_acc}` — dropping `structure_digest`, `chunk_count`, `pc`, `public_trace`. The parity-test reference builder was updated identically. But the **native** `state_x_out_digest` still hashes the OLD FULL preimage with ASCII tag `b"neo.fold.clean/state_x_out/v1"` and all 10 fields. The new domain const is defined (`digest.rs:68`) but unused by the native fn. The migration is half-done; the diff even *adds* a doc at `digest.rs:694-697` claiming the wide preimage is "intentionally" retained, contradicting the same changeset.
- **Where:**
  - `crates/neo-fold-clean/src/paper/digest.rs:699-723` (tag at 711; native still absorbs 10 fields)
  - `crates/neo-fold-clean/src/paper/f_prime/digest_circuit.rs:108-130` (reduced domain at 112, 6-field preimage 112-125)
  - `crates/neo-fold-clean/src/paper/construction2/transition.rs:160-174` (`compute_x_out` uses native full)
  - `crates/neo-fold-clean/src/engine/decider.rs:1355-1368, 773, 836-858` (`state_x_out_lanes` → native full → `push_enc_inst`)
  - tests: `phase_1_mini_1_state_x_out.rs:207-209`; also `tests/f_prime/digest_circuit.rs:138/162/181/211` and `tests/f_prime/r1cs.rs:399-414, 449, 633`
- **Paper invariant:** `NIVC-DIGEST-IO-BINDING` (HyperNova §6.3 Construction-2 F'_j step 5 / Verifier step 3 — in-circuit output hash and consumer hash must bind the same fields in the same order); `SN-S6-COMPLETENESS-INSTANCE-EQUALITY`.
- **Failure mode:** Native-full hash ≠ circuit-reduced hash (different domain encoding **and** different field set). The decider R1CS pins source-image public bits (computed from native-full `state_x_out_lanes`) equal to `bit_decompose(circuit-reduced digest)` via `enforce_x_out_public_bit_wires` → unsatisfiable. The terminal-fold pin (`decider.rs:1318-1331`) breaks the same way. This is **liveness/correctness** — native prove and native verify both use the stale full hash consistently, so it is **not** a false-accept; only the native↔circuit boundary diverges. Net effect: valid IVC proofs become uncompressible/unlinkable once Spartan is wired, and ≥3 committed parity/step tests now fail. (Currently masked from the shipped compress entrypoint only because `paper::decider::prove` is a `Err(Unsupported)` stub at `paper/decider.rs:311-313`; the R1CS synthesis is nonetheless exercised by the tests above.)
- **Fix:** Complete the migration natively. In `state_x_out_digest`, replace the ASCII-tag seed with `vec![F::from_u64(F_PRIME_STATE_X_OUT_DOMAIN)]`, keep `{vk_fs, step_count, initial_boundary, current_boundary, semantic_acc, construction2_acc}`, and delete the absorbs of `structure_digest`, `chunk_count`, `pc`, `public_trace` so the field set/order matches `enforce_state_x_out_digest_circuit` and `build_state_x_out_preimage` byte-for-byte. Trim the now-unused params from the signature and the call sites (`decider.rs:1356`, `transition.rs:161`, F' callers). Delete the contradictory doc at `digest.rs:694-697`. Re-run the three parity/step test files. (Each dropped field's rationale must independently hold — structure subsumed by `vk_fs`, `pc` constant for ℓ=1, `public_trace == z_i`, `chunk_count` non-binding; if any fails for a target frontend, revert the *circuit* to full instead.)

## Medium

### R1CSFP-2 — Packed-bit public-input mode accepted with no check that packed variables are 1-bit/Boolean-constrained → public-input→digest binding can be non-injective

- **What/where:** `derive_structure` validates packed mode purely via `app_public_input_bit_var_indices == (0..m_in)` and empty `app_public_input_var_indices` (`crates/neo-fold-clean/src/frontends/r1cs_f_prime/mod.rs:457-468`, `packed_public_input_ok`). The `PlanAppPrivateBooleanWidthUnconstrained` gate (`mod.rs:421-431`) only checks `app_private_var_widths` 1-bit entries — a *separate* field — never the packed indices. `AppAssignmentBitPack` (`crates/neo-fold-clean/src/frontends/f_prime/structure.rs:1076-1088`) packs `Σ_k 2^k · app_variable_terms(lane_k)`; a 64-bit slot makes `app_variable_terms` return a full `Σ_{i<64} 2^i·bit_i` recomposition, so the pack becomes `Σ_k 2^k·(Σ_i 2^i·bit_{k,i})` — overlapping weights, non-injective over field-valued vars.
- **Paper invariant:** `DIGEST-BIND-014` / `CCS-CHAL-ORDER-003` / `NIVC-DIGEST-IO-BINDING` (Def. 22: R1CS `x ∈ F^ℓ` is field-valued, not `{0,1}`; the output hash must faithfully bind IO). The surrounding code asserts this binding must be injective (`mod.rs:445-452`).
- **Failure mode:** With `app_private_var_widths` empty all app vars default to 64-bit lanes and the width-1 check is skipped entirely; the checked-in test `sha256_state_x_out_packs_public_input_bits_static_layout` uses exactly this config and is accepted. Two distinct field-valued public inputs `x ≠ x'` can collapse to the same packed lane → same `public_output_digest` → verifier accepts a proof for the wrong statement. Not exploitable against the shipped Boolean-input SHA deployment (bellpepper allocates digest bits as `AllocatedBit`, so `boolean_constrained_variables` propagates), but the validator admits the mode for arbitrary non-Boolean-input R1CS the paper explicitly permits. The compiler-side reject (`compiler.rs:485-497`) filters only the honest prover and is not soundness-binding.
- **Fix:** When `packed_public_input_ok` holds, compute `boolean_constrained_variables()` and reject any packed `index` not Boolean-constrained (new `Error::PackedPublicInputNotBooleanConstrained { index }`), mirroring the existing width-1 gate. This forces each packed lane to recompose a `{0,1}`-pinned variable so `Σ_k 2^k·z_k` is injective. Optionally also require those indices carry width-1 in `app_private_var_widths` when typed widths are present. Add a non-Boolean-public-input packed-mode test that must now fail at preprocess.

### R1CSFP-3 — Boolean detector's copy-row propagation (and seed) assume R1CS constant column `z[0]=1`, but the F' shell never pins the app constant lane to 1

- **What/where:** `boolean_constrained_variables()` propagates "is Boolean" across copy rows where `B == is_one_lc` (exactly column 0, coeff 1), reading column 0 as the literal constant 1 (`crates/neo-fold-clean/src/frontends/r1cs_f_prime/structure.rs:200-216, 293-345`). But the F' encoding maps R1CS variable 0 to `app_assignment_lanes[0]` (`encoder.rs` `fill_app_private`) — a **committed** lane, NOT the CCS constant `z[0]`, and **not pinned to 1** anywhere; `append_r1cs_rows` only enforces `(Az)(Bz)=(Cz)`. The same col-0=1 assumption also affects the *seed* detector `boolean_row_var`, not just propagation.
- **Paper invariant:** `FOLD-WITNESS-COMMITMENT-INSTANCE-SPLIT` (constant-1/u-slot must be structurally pinned; Def. 22 `Z=(W,x,1)`); `CE-REL-001`.
- **Failure mode:** Gated on R1CSFP-1 (app-private columns no longer bitness-constrained) plus the `{-1,0,1}` norm bound (`within_nc_bound` accepts balanced −1 for b≥2): an F'-satisfying assignment can set app-var-0 = −1. Then a copy row `c·z[a]·z[0]=c·z[b]` with `z[a]=1, z[0]=−1` forces `z[b]=−1`, which a 1-bit slot admits — so a variable the detector marked Boolean (single committed column, possibly bit-packed into `state_x_out`) holds −1, contradicting the `{0,1}` premise behind the slot and the packed binding. Exploitability requires the whole R1CS to remain satisfiable with constant ≠ 1 (honest circuits like SHA-256 likely force it; the frontend accepts arbitrary R1CS and provides no guarantee). The decider trusts the resulting `x_out`/`public_output_digest` without re-deriving `x` or checking constant=1 (`decider.rs:212-228`).
- **Fix:** Pin the constant lane structurally: in `build_r1cs_f_prime_structure` (after `append_r1cs_rows`) emit one linear row binding `app_assignment_lanes[CONST_IDX] == z[0] == 1` (CONST_IDX=0 for bellpepper), aligning with `Z=(W,x,1)`. This makes both the seed `z·(1−z)=0` rows and copy-row propagation sound regardless of how the prover fills the lane. **Only fully closed together with restoring bitness rows on typed 1-bit app-private slots (R1CSFP-1).** If the frontend must accept R1CS with no designated constant column, instead drop `is_one_lc`-based seeding/propagation so no Boolean claim is derived from an unpinned constant. Add a regression test: an R1CS satisfiable with constant = −1, a copy-row-propagated 1-bit slot set to −1, asserting the structure now rejects.

## Lower-severity / hygiene

- **NR-1 (low, completeness):** New `if !z_blocks.re_nonzero[blk] { continue; }` guards in the complex ring evaluators (`superneo_eval.rs:712-715, 794-797, 1090-1093`) skip a block on real-part==0 but still consume `z_blocks.im`, dropping `bar(M)·z_im` when real lanes cancel across carried instances under K-valued γ. Verifier re-checks CE via a separate real-only path so this is a *rejected valid proof*, not a false-accept; trigger ≈ exact full-block real cancellation (negligible). Fix: add per-block `im_nonzero` and skip only when both lanes are zero.
- **F1 (low, completeness):** Eval table dropped via `carried_z_blocks.real_all_zero()` (`oracle.rs:1215`), which inspects only real lanes; a non-real γ can leave real lanes zero but imaginary nonzero, dropping a live Eval term while `T` still includes it → honest proof rejected (~1/|F|). Fix: gate on `real_all_zero() && imag_all_zero()` (or add `is_zero()`).
- **fprime-frontend (low):** `state_x_out` drops `pc` — sound only for ℓ=1 (pc pinned to `TRIVIAL_PC`); becomes a soundness obligation if multi-pc (ℓ>1) is ever enabled. Boundary chain collapsed to `z_{i+1}=chunk_digest` (drift from `z_{i+1}=F(z_i)`); content authority moved to the accumulator path — worth a spec note.
- **digest-binding-state (low):** `state_x_out` field drops retained transitively but several invariants now depend on out-of-hash pins; base step does not enforce `rows_in_chunk≥1` (harmless for single base). Over-stated comments in `state.rs`/`transition.rs` imply universal enforcement of `semantic_state_digest == acc_digest` (true only on the re-walk path; not a decider R1CS row — masks the latent gap). `AccumulatorHandleOpening` and legacy `from_*` constructors are newly-added/now-dead surface — remove per project rule.
- **lifecycle (low):** `Cargo.toml` adds `rayon = { workspace = true }` to `neo-fold-clean` — references an existing workspace dep (no new external dep) but per AGENTS.md surface for explicit approval; no soundness impact.
- **tests (low):** `phase_1_3d_step_parity` `new_acc_digest` assertion is now tautological (both sides from the same call; circuit no longer computes it) — dead coverage for that lane (real binding covered elsewhere). New `enforce_ring_mul_toom3` has only single-seed positive parity coverage; recommend negative/property tests. Default-running threaded fold test proves but does not verify the delayed-handle chain (end-to-end verify behind `#[ignore]`).
- **paper-reductions (low):** Multi-fold combined-sum-check γ batching lives in `neo-reductions` oracle/superneo_eval (outside the paper-layer diff); off-by-one/exponent-collision (`CCS-Q-STRUCT-002`/`MF-RLC-GAMMA-EXPONENTS`) cannot be ruled out from the paper-layer diff alone — area of attention, not a confirmed defect.

## Not covered / residual risk

- **Cargo.lock excluded:** `M Cargo.lock` was not audited; dependency-graph changes (beyond the surfaced `rayon` reference) not reviewed.
- **Tests were NOT executed.** All findings are static. In particular NFC-1's predicted unsatisfiability and ≥3 failing parity/step tests (`phase_1_mini_1_state_x_out.rs`, `tests/f_prime/digest_circuit.rs`, `tests/f_prime/r1cs.rs`) are inferred from the diff, not observed via a test run.
- **Spartan compress path is a placeholder** (`paper::decider::prove` → `Err(Unsupported)`). Several gaps are *latent today* and only become live once Spartan is wired: the NFC-1 uncompressibility against the user-facing entrypoint, and the missing `semantic_state_digest == acc_digest` decider R1CS row. They were judged as if that path were live.
- **Multi-fold γ-batching kernel** (`neo-reductions` oracle.rs / superneo_eval.rs) is the most-rewritten multi-instance-sensitive code; γ-exponent separation was argued algebraically and is partly guarded by `superneo_eval_equivalence.rs`, but the chunked-accumulation reduction-order paths and µ>1/ν>1 distinct-exponent cases are not exercised by the new tests — not exhaustively verified.
- **Bit-validity scope reduction** (committed lanes weakened from `{0,1}` to signed `{-1,0,1}`) shifts soundness onto a "collision-resistance + value-level consistency + bit-pinned public output" argument; the fprime auditor explicitly recommends a confirming adversarial test (and a council pass) before relying on it — not done here.
- **ℓ>1 / multi-pc and non-Boolean-input R1CS** are out of the shipped deployment but admitted by the frontend; R1CSFP-2/-3 are reachable only there, and that reachability was reasoned, not exercised.
- **R1CSFP-1 caveat:** R1CSFP-3 cites a precondition "R1CSFP-1 — typed 1-bit app-private slots are not bitness-constrained" that the R1CSFP-3 verifier independently confirmed holds in code (`semantic_boolean_columns` skips app-private when `app_private_var_widths` is non-empty), but R1CSFP-1 was not itself emitted as a standalone confirmed finding (the `audit:r1cs-fprime-frontend` agent stalled and retried once). Treat the app-private bitness gap as a real, load-bearing item to fix alongside R1CSFP-2/-3.
