Shared recomposition experiment for Nico
=======================================

This branch contains a test-only prototype, not a production optimization.
It is based on origin/nico/f-prime-constraints-cuda-formal at df0abe0dd.
The original experiment was at 0b43e1912bb4a83e296339d6d4d093e19d766d05.
No verifier, transcript, commitment, witness encoding, or production dispatch
changes. No dependency on the other exploratory experiments.

What it does
------------
The encoded matrices repeat geometric runs over the same witness coordinates.
Plan::new indexes runs by (start, length, ratio), independently of the scalar
coefficient. Each evaluation computes each distinct run once and applies the
original scalar coefficients to those cached values. The plan depends only on
the relation. Values are recomputed for every witness or projected input;
values are never reused across different folds.

The fresh path reconstructs packed signed-unit coordinates in F. The carried
path applies the same factorization over K after the existing ring projection.
All other protocol terms and the complete production sumcheck remain intact.
Final ring openings are unchanged. The opening helper only measures them.

Treat its reproduction commands as historic; use the commands below instead.

The plan costs about 0.9-1.0 seconds to build and retains 643.13 MiB.

Reproduce from the repository root
----------------------------------
Requires Python 3 and the repository Rust toolchain. The embedded application
artifact is used directly; no Lean build or external fixture download is needed.
All commands enforce a 300-second cap per cargo-test process, including builds.
If compilation reaches the cap, that invocation fails; rerun after partial build.
Do not run benchmark processes concurrently. Release profile and four Rayon
threads are fixed. Each benchmark warms up and consumes/checks its outputs.

python3 experiments/recomposition/run.py capture
python3 experiments/recomposition/run.py checks
python3 experiments/recomposition/run.py measure --step 1
python3 experiments/recomposition/run.py measure --step 2
python3 experiments/recomposition/run.py measure --step 3
python3 experiments/recomposition/run.py proofs --step 1 --pairs 5 --processes 4
python3 experiments/recomposition/run.py proofs --step 2 --pairs 5 --processes 4
python3 experiments/recomposition/run.py proofs --step 3 --pairs 5 --processes 4
python3 experiments/recomposition/summarize.py

Each proofs process runs one warmup pair and then --pairs measured pairs. With
--processes N, run.py runs N processes in sequence, waits --cooldown seconds
(default 30) between them, and writes all records to one JSONL file. Five pairs
of state 3 fit in the 300-second cap; more pairs per process do not.
Use --target-dir PATH to share an existing Cargo build directory, --directory
PATH for captured witnesses (default: nightstream-recomposition-handoff in the
system temporary directory), and --output PATH for logs/JSONL (default
experiments/recomposition/results). Pass --results PATH to summarize.py if
changing the output location.
Large captured witnesses are not committed. Raw current JSONL results are.

Code map
--------
crates/neo-reductions/tests/experiments/recomposition.rs:
  standalone relation adapter, plan, fresh/carried kernels, differential timings.
crates/neo-reductions/tests/experiments/recomposition_proof.rs:
  test backend, alternating production/factored complete PiCCS comparisons.
  Both variants enter through the same backend; production calls the unchanged
  OptimizedPaperJointOracle::new. A wrapper times each oracle phase, and a
  counter on the matrix-row source records window builds in each phase.
  Like the prover's PackageRows, the row source keeps one RetainedMatrixWindow
  for all proofs of a process, and the proofs use the prover's own row
  workspace (workspace.json, written by the capture).
  Every proof verifies; output claims and sumcheck round messages agree exactly.
crates/neo-reductions/tests/experiments/recomposition_openings.rs:
  diagnostic split of unchanged opening evaluation, checked against production.
crates/nightstream/tests/experiments/recomposition_capture.rs:
  real application prove + two extends, captures active witnesses and claims,
  writes the prover's matrix_workspace_bytes, and verifies the final lifecycle
  proof.
All implementation hooks are cfg(test). The only dependency addition is a
neo-reductions dev-dependency on nightstream-fprime.

Before production integration
-----------------------------
Give the plan explicit relation ownership and budget its retained and temporary
memory. Avoid constructing it on every fold. Keep cached values local to each
evaluation. Preserve the ring projection before factoring carried evaluations;
ordinary field reconstruction does not replace the required ring map.
The prototype accepts packed signed-unit or virtual-zero witnesses only.
A production path needs an explicit policy for other representations and small
relations where plan setup will not amortize. The test backend currently uses
one fresh witness, matching this workload. It is not a general public backend.
Keep full-proof differential tests and verifier checks when integrating.

builds were not a real cost.
