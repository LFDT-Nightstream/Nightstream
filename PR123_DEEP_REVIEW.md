**Why the proposed relocation direction is appropriate**

The necessary assumptions are: one application circuit owns the semantics; the archive must contain its exact compiled rows; relocation must preserve values and supported reads; and the selected profile stays fixed. Keeping an old runtime mode is not needed for any of those obligations.

The [Program contract](/Users/nijaar/starstream/Nightstream/formal/nightstream-fprime/NightstreamFPrime/Lifecycle/Stage1/Application.lean:12) gives semantic equivalence and supported variable reads. It does not require two compilations at different offsets to have identical syntax. [ApplicationRelocation.plan](/Users/nijaar/starstream/Nightstream/formal/nightstream-fprime/NightstreamFPrime/Export/Stage1/Wide/ApplicationRelocation.lean:75) follows that direction.

**The intended single implementation path**

The relevant assumptions are explicit. A single supported protocol and no deprecated compatibility are user requirements. Distinct protocol phases and physical/logical representations are required by the mathematics and the emitted-package design. CPU and Metal are permitted arithmetic engines for the same relation. Keeping the old sampler executable, old artifact formats, or application-specific dispatch is not needed by those requirements.

```text
Lean protocol and general application
  -> proved logical circuit
  -> proved physical layout and application relocation   [R2 open]
  -> one wide package + shared manifest + bindings        [R1 open]
  -> Circuit::compile / trusted saved Circuit
  -> Prover::prove / Prover::extend
  -> one physical witness executor
  -> one retained logical assignment transport
  -> PiCCS -> wide PiRLC -> PiDEC
  -> fresh CCS claim + 16 running CE claims
  -> Verifier::verify against an external state
```

[Assembly](/Users/nijaar/starstream/Nightstream/crates/nightstream/src/assembly/mod.rs:43) validates the pinned reference independently from the assembled candidate. Candidate self-consistency does not authorize the reference. [Public extension](/Users/nijaar/starstream/Nightstream/crates/nightstream/src/circuit.rs:134) executes the application and passes its values into completion. [Completion](/Users/nijaar/starstream/Nightstream/crates/nightstream/src/lifecycle/complete.rs:147) uses one entrypoint. [That entrypoint](/Users/nijaar/starstream/Nightstream/crates/nightstream-fprime/src/package/sealed.rs:420) executes the physical program and then applies the retained assignment transport.

Reusing cached application values is a computation choice inside this path. The input/output frame and rows still check those values. It does not select a second relation.

The terminal verifier checks the external state, base case, child count, common point, public projections, fixed-key commitments, fresh CCS rows, and both running evaluation families. **The wide sampler: what is correct, and what its bound does not prove**

For Goldilocks modulus `p`, the sampler reads four canonical values in this order:

    X = h0 + p*h1 + p^2*h2 + p^3*h3
    R = X mod 5^54
    rho[j] = digit_base_5(R, j) - 2, for j = 0,...,53

The [Rust decoder](/Users/nijaar/starstream/Nightstream/crates/neo-reductions/src/common/pi_rlc_wide.rs:9) implements that map with four 64-bit limbs. Taking the first 54 base-five digits of `X` is exactly reduction modulo `5^54`. The [Lean definition](/Users/nijaar/starstream/Nightstream/formal/nightstream-fprime/NightstreamFPrime/Spec/Folding/Nifs/NonInteractive/PiRlcWideSampler/Definition.lean:47) fixes the same order. Each coefficient is in `[-2,2]`. There is no rejection loop and no sampler-abort event.

The circuit also checks the map. It constrains the four canonical field words, quotient bits, digit bits, digit ranges, and six modular equalities. Bounds and the Chinese remainder theorem turn those equalities into the integer relation `X = Q*5^54 + R`. The soundness theorem permits arbitrary witness hints; it does not assume that the hint producer is honest. This is a necessary implementation link beyond the probability calculation. [Sampler gadget soundness](/Users/nijaar/starstream/Nightstream/formal/nightstream-fprime/NightstreamFPrime/Gadgets/Sampling/WideReduction/Soundness.lean:173).

For one scalar, let `M = p^4`, `N = 5^54`, and `r = M mod N`. Under four independent uniform field values, the exact total-variation distance from a uniform strong-set scalar is:

    delta = r*(N-r)/(N*M) < 2^-132

The proof counts `floor(M/N)` or `floor(M/N)+1` draws for each residue. [Sampler law](/Users/nijaar/starstream/Nightstream/formal/nightstream-fprime/NightstreamFPrime/Spec/Folding/Nifs/NonInteractive/PiRlcWideSampler/Law.lean:12).

I recomputed the integers used in that formula. The exact scalar distance is approximately `2^-132.98`. For an independent batch of 17 scalars, `17*delta` is approximately `2^-128.89`. The separate coordinate-fork extraction loss `17/5^54` is approximately `2^-121.30`. These values describe different events. None is a selected total security level.

The new runtime absorbs the scalar tag and coordinate, squeezes one four-field digest, and decodes it. [Runtime sampler](/Users/nijaar/starstream/Nightstream/crates/neo-reductions/src/common.rs:814). The verifier context binds the wide schedule. Thus this is a real protocol-schedule replacement, not a local arithmetic optimization with unchanged transcript bytes.

The selected [Fiat–Shamir model](/Users/nijaar/starstream/Nightstream/formal/nightstream-fprime/NightstreamFPrime/Lifecycle/Nifs/WideFiatShamir.lean:116) assumes a transfer from success of the actual wide verifier to the typed interactive experiment. The model supplies `g` and `deltaFS`; it does not prove that Poseidon2 output is independent uniform data. The separate adaptive sampler comparison counts oracle calls and is not consumed directly by the extraction theorem. [Recorded model scope](/Users/nijaar/starstream/Nightstream/docs/reviews/nightstream-fprime-requirements/FIAT_SHAMIR_MODEL.md:82).

The source correctly distinguishes these boundaries. It supports a conditional result, not a complete numerical classical or quantum security claim. The Rust minimum-security check also describes a statistical census, not the complete FS/MSIS security model. I did not establish a supported input for which omission of an explicit sampler term changes its accepted integer threshold; that is not raised as a parameter-validation bug.
